# Model report

Generated by `model/train.py`. **All data is synthetic** (`model/generate.py`, seed 20261108); these numbers show the mechanism works on the patterns we generated, not real-world accuracy.

## Setup

- 6,000 sequences (3,000 normal, 600 per attack pattern), split 60/20/20 by sequence.
- Features (9): `frac`, `gap`, `burst`, `rush`, `flow`, `recipAge`, `fresh`, `freshFlow`, `size` (definitions in the README).
- Architecture chosen on validation: 9 -> **12** ReLU -> 1. Candidates: 8 hidden = 59.0% val detection, 12 hidden = 60.4% val detection, 16 hidden = 60.4% val detection.
- Quantized weights: layer 1 x2^20, layer 2 x2^14; score = logit x 256. |float - integer| score difference over all spends: mean 1.02, p99 3.23, max 10.75 score units (256 = 1.0 logit).
- Threshold **472** (logit 1.84): the lowest value that freezes at most 1.0% of *validation* normal sequences (60 spends each). The baseline gets the same budget.
- Freeze latency assumed for the loss columns: 10 s after the flagged spend (spends inside that window still go through).
- weights sha256 (quantized section): `8def20e668238a9353f2658a403a0bf9a0a8650b4744d7edcee5365726b61689`

## What the network adds

At the same false-freeze budget the network detects 57.1% of held-out attacks versus 39.8% for the best single-feature rule `freshFlow >= 951` (+17.2 points), and the mean share of balance lost is 26.3% versus 28.3% (no guard: 48.3%).

- Patterns where the network detects more: burst, drip, spray, mimic.
- Patterns where the single rule detects more: sweep.
- Each single feature tracks one symptom: a short gap or a high short-window outflow also occurs in normal batch payments, and a new recipient occurs whenever the agent adds a vendor. The network weighs several symptoms together; on this data that gives more detections at the same false-freeze budget, at every budget in the table above.
- `mimic` (normal amounts at normal pace to one new address) looks like a normal agent adding a vendor under these features; neither method catches it reliably. The per-call cap is the only bound on that pattern.
